# Explorer OCR and page ranges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the confirmed OCR progress-file race and add undoable keep/remove page ranges.

**Architecture:** Bounded atomic-report retries retain the current subprocess protocol. A pure range parser feeds one Qt dialog and the existing project/undo/export flow.

**Tech Stack:** Python, PySide6, PyMuPDF, ONNX DirectML, PyInstaller, Inno Setup.

**Spec:** docs/superpowers/specs/2026-11-19-ocr-pages-design.md

## Global Constraints
- Local OCR; source PDF unchanged on failure; preserve exact backup and original appearance.
- Keep editable project objects and Ctrl+Z/Y; physical 1-based page numbers; keep source order.
- No Windows screen capture; static Qt widget grabs only.
- Public source and 0.4.0 updater; no user PDF committed or uploaded.

## Review Focus
- Real Windows reader denies delete-sharing while progress is published.
- Junk between digits and hyphens; duplicates, overlapping and adjacent ranges.
- Huge/out-of-bounds or malformed ranges must not allocate unbounded results.
- Removing the current/last page; no empty document; keep objects and undo/redo.
- Long document through the packaged Explorer dialog, not only the worker.
